接三顆 LED,用變數、陣列和 for 讓程式變短

三組一模一樣的電路,先用最笨的寫法讓它動,再一步步改成變數、陣列加 for 迴圈。效果相同,程式越來越短、越好改。

TL;DR 三顆 LED 的負極共用一條 − 軌,正極各經過 220Ω 電阻接到 8、9、10 號腳。程式寫三次:直接寫、用變數命名、陣列加 for。陣列編號從 0 開始,迴圈條件寫 i < 數量。

三顆燈都想閃:每顆都寫一遍太累了

上一篇一顆 LED 只要幾行。三顆就要把同樣的事情寫三遍;十顆呢?這一篇學三個工具,讓程式變短、也變好改:

小技巧這一篇的程式有四個版本(寫法一到三,再加一個挑戰),做出來的效果完全相同。差別只在於程式碼的長短與好不好改,你會親眼看到它們怎麼一步步變短。

接線:三組「電阻 + LED」,共用一條 GND

每一組的接法和上一篇完全一樣(訊號腳 → 電阻 → LED → GND),只是做三次。新的做法是:三顆 LED 的負極都接到同一條電源軌,再用一條線回到 Uno 的 GND,不必拉三條。

圖只畫左邊 22 欄,你的麵包板更長,以欄號與 a–j 為準(手機上可以左右滑動圖)。如果你的麵包板電源軌中間是斷開的(第 2 篇),黑色短線與 GND 線要接在同一半:上面圖中 t-8、t-14、t-20、t-22 都在同一條軌上,請確認它們彼此相通。

四個版本的程式,效果完全相同

寫法一:最直接,但很長

寫法一:每顆燈都寫一遍
// 第 4 篇(寫法一):三顆燈,每顆都寫一遍
void setup() {
  pinMode(8, OUTPUT);
  pinMode(9, OUTPUT);
  pinMode(10, OUTPUT);
}

void loop() {
  digitalWrite(8, HIGH);   // 第一顆亮
  delay({ms});
  digitalWrite(8, LOW);    // 第一顆滅

  digitalWrite(9, HIGH);   // 第二顆亮
  delay({ms});
  digitalWrite(9, LOW);

  digitalWrite(10, HIGH);  // 第三顆亮
  delay({ms});
  digitalWrite(10, LOW);
}

能動,但每多一顆燈就要複製三行。而且腳位數字 8、9、10 散在好幾處,想換腳位要一個一個改,很容易漏。

寫法二:用變數替腳位取名字

寫法二:變數與常數
// 第 4 篇(寫法二):用變數替腳位取名字
const int RED_PIN = 8;       // 常數:值不會變
const int YELLOW_PIN = 9;
const int GREEN_PIN = 10;
int waitMs = {ms};           // 變數:之後可以改它的值

void setup() {
  pinMode(RED_PIN, OUTPUT);
  pinMode(YELLOW_PIN, OUTPUT);
  pinMode(GREEN_PIN, OUTPUT);
}

void loop() {
  digitalWrite(RED_PIN, HIGH);
  delay(waitMs);
  digitalWrite(RED_PIN, LOW);

  digitalWrite(YELLOW_PIN, HIGH);
  delay(waitMs);
  digitalWrite(YELLOW_PIN, LOW);

  digitalWrite(GREEN_PIN, HIGH);
  delay(waitMs);
  digitalWrite(GREEN_PIN, LOW);
}
這一行
它在做什麼
const int RED_PIN = 8;
宣告常數:int 是型態(整數),RED_PIN 是名字,8 是值。const 表示它不會被改。之後用 RED_PIN 就等於用 8。
int waitMs = 300;
宣告變數(沒有 const):值可以在程式裡被改。這裡存「每顆燈亮多久」。
delay(waitMs);
用變數代替數字。想調速度,只改最上面那一行。
小技巧取名字的規則:用英文字母開頭,只用英文、數字與底線 _,不能有空格,而且大小寫不同就是不同名字(waitMs 與 waitms 是兩個東西)。

寫法三:陣列 + for 迴圈

寫法三:陣列與 for 迴圈
// 第 4 篇(寫法三):陣列 + for 迴圈
const int ledPins[] = {8, 9, 10};   // 陣列:把三個腳位放在一排
const int LED_COUNT = 3;            // 一共幾顆燈
int waitMs = {ms};

void setup() {
  for (int i = 0; i < LED_COUNT; i++) {
    pinMode(ledPins[i], OUTPUT);    // 對每一顆燈做一次
  }
}

void loop() {
  for (int i = 0; i < LED_COUNT; i++) {
    digitalWrite(ledPins[i], HIGH);  // 第 i 顆亮
    delay(waitMs);
    digitalWrite(ledPins[i], LOW);   // 第 i 顆滅
  }
}
這一行
它在做什麼
const int ledPins[] = {8, 9, 10};
陣列:一排有編號的盒子。方括號 [] 表示這是陣列,大括號裡是內容。
ledPins[0]、ledPins[1]、ledPins[2]
取出第幾格的值。編號從 0 開始:ledPins[0] 是 8,ledPins[1] 是 9,ledPins[2] 是 10。
for (int i = 0; i < LED_COUNT; i++) { … }
for 迴圈:把大括號裡的事重複做。括號裡三段用分號隔開,見下表。
ledPins[i]
每一圈 i 不同,取到的腳位就不同。同一行程式,三顆燈各做一次。

for 括號裡的三段

寫法
意思
什麼時候做
int i = 0
起點:建立計數器 i,從 0 開始。
進迴圈前,只做一次
i < LED_COUNT
條件:i 小於 3 才繼續。
每一圈開始前檢查,不成立就結束
i++
每圈做完:i 加 1(等於 i = i + 1)。
每一圈結束時

跑一遍會怎樣(LED_COUNT = 3)

第幾圈
i 的值與腳位
動作
第 1 圈
i = 0 → ledPins[0] = 8
紅燈亮、等待、熄滅
第 2 圈
i = 1 → ledPins[1] = 9
黃燈亮、等待、熄滅

你會看到三顆燈由左到右依序亮起,一次只亮一顆,一輪 0.9 秒,不斷重複。紅 → 黃 → 綠 → 紅 …
小技巧三個版本會做出一模一樣的效果。要多一顆燈,寫法三只需要加一個腳位到陣列、並把 LED_COUNT 改成 4;寫法一要再複製三行,還得記得 setup() 也要加。

// 挑戰:來回跑(像霹靂遊俠的車頭燈)
const int ledPins[] = {8, 9, 10};
const int LED_COUNT = 3;
int waitMs = {ms};

void blinkOne(int i) {               // 自己定義一個函式:亮第 i 顆再熄滅
  digitalWrite(ledPins[i], HIGH);
  delay(waitMs);
  digitalWrite(ledPins[i], LOW);
}

void setup() {
  for (int i = 0; i < LED_COUNT; i++) {
    pinMode(ledPins[i], OUTPUT);
  }
}

void loop() {
  for (int i = 0; i < LED_COUNT; i++) {               // 往右:0 → 1 → 2
    blinkOne(i);
  }
  for (int i = LED_COUNT - 2; i > 0; i--) {           // 往左:1(頭尾不重複)
    blinkOne(i);
  }
}
這一行
它在做什麼
void blinkOne(int i) { … }
自己定義的函式:把「亮第 i 顆再熄滅」這件事取名叫 blinkOne。括號裡的 int i 是它收到的資料(第幾顆)。
blinkOne(i);
呼叫它。要做這件事就寫名字,不用重寫三行。
for (int i = LED_COUNT - 2; i > 0; i--)
從倒數第二顆往回數到第 1 顆(i-- 是每圈減 1),頭尾那兩顆不重複亮,動作才順。

常見卡關

只有某一顆燈不亮,另外兩顆正常

程式對三顆燈是一樣的做法,所以問題幾乎一定在那一列的接線。依序檢查那一組:

  1. LED 的長腳在不在靠電阻的那一側(插反最常見)。
  2. 電阻右腳與 LED 長腳是否在同一欄。
  3. LED 短腳那一欄的黑色短線,是否真的接到 − 軌。
  4. 訊號線是否插在正確的腳位(8、9、10),且插在電阻左端那一欄。
三顆燈全不亮

先檢查共用的部分:Uno 的 GND 線有沒有接到 − 軌、− 軌有沒有中間斷開、USB 有沒有接上、程式有沒有成功上傳。三條路共用同一條 GND,這條線沒接就全部不亮。

燈亮的順序和我想的不一樣

順序由陣列決定:{8, 9, 10} 是先 8、再 9、再 10。如果實際位置的順序不同,檢查哪條訊號線接到哪一組,或直接調整陣列裡數字的順序。

迴圈寫成 i <= LED_COUNT,結果怪怪的

i <= 3 會多跑一圈,取到 ledPins[3]。但陣列只有 0、1、2 三格,第 3 格不存在,Arduino 不會報錯,而是讀到記憶體裡的別的東西,可能去控制一個你沒接任何東西的腳位。記住:n 個元素,編號是 0 到 n−1,條件寫 i < n。

驗證出現紅字錯誤

新手最常見:陣列漏了 []、大括號 { } 沒成對、for 括號裡的分號寫成逗號、少了結尾分號。IDE 會指出行號,從那一行與上一行找起。
