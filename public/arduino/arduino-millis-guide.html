讓 Arduino 同時做好幾件事：不要睡覺，改看時鐘

delay() 讓 Arduino 睡覺，會漏掉按鈕。學會 millis()：不卡住的計時，讓閃燈、按鈕與別的工作各自按自己的節奏進行。

TL;DR delay() 期間什麼都看不到。millis() 回傳開機後的毫秒數。固定寫法：if (現在 - 上次 >= 間隔) { 上次 = 現在; … },變數用 unsigned long,loop() 裡不要 delay()。每件定時的事各用一個「上次」變數。

delay() 的問題：它在睡覺，什麼都不做

到目前為止，我們用 delay() 等時間。但 delay(500) 的意思是：Arduino 整整睡 0.5 秒，期間什麼都不看、什麼都不做，包括按鈕。想要「LED 一直閃，同時還能按按鈕」，用 delay() 就會漏掉按鈕。

先親眼看一次

下面並排兩個版本：delay() 版（每 1 秒才看一次按鈕）與 millis() 版（隨時都在看）。點「按一下按鈕」，看黃燈的反應。可以多點幾次、點在不同時間：

小技巧這就是為什麼 delay() 只適合「同時只做一件事」的簡單程式。一旦要「同時做好幾件事」（閃燈、讀按鈕、量距離、更新螢幕……），就要換成 millis() 的寫法。第 18 篇的綜合專案就靠它。

millis()：看一眼時鐘，而不是站著等

比喻：煮泡麵

delay(180000) 像是站在爐子前面盯著鍋子三分鐘，什麼都不能做。millis() 像是記下現在幾點，然後去忙別的事，時不時看一眼時鐘：「現在離我下鍋已經過 3 分鐘了嗎？」到了才關火。

millis() 回傳「從開機到現在，過了幾毫秒」，型態是 unsigned long（只有正數、很大的整數）。這個數字一直往上跑。

固定的寫法

unsigned long now = millis();
if (now - previousMillis >= INTERVAL) {   // 距離上次已過 INTERVAL 毫秒?
  previousMillis = now;                   // 記下這次的時間
  // 在這裡做你要定時做的事
}
  1. 每一件定時的事，各用一個 previousMillis 變數記「上次是什麼時候」。
  2. 判斷用減法：現在 − 上次 ≥ 間隔,不要用 現在 ≥ 上次 + 間隔。
  3. 整個 loop() 裡不要有 delay()。
為什麼用減法
說明
unsigned long 會「繞一圈」
它最大約 42.9 億，毫秒數跑到上限（約 49.7 天）會歸零重新開始。
減法剛好不受影響
無號整數相減，即使中間歸零，算出的「過了多久」仍然正確。用加法比較就會在那一刻出錯。
型態要對不要把 millis() 的結果放進 int。int 最大只能放 32767，約 32 秒就溢位，程式會莫名其妙壞掉。一定要用 unsigned long。

先填入紅燈閃爍的間隔

空白時顯示範例值；橘底文字就是會被替換的部分。

寫法一：不用 delay 讓 LED 閃

millis() 版 Blink
// 第 15 篇(寫法一):不用 delay 讓 LED 閃爍
const int LED_PIN = 8;
const unsigned long INTERVAL = {interval};   // 每隔幾毫秒切換一次
unsigned long previousMillis = 0;            // 上一次切換是什麼時候
bool ledOn = false;

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  unsigned long currentMillis = millis();                  // 現在是開機後的第幾毫秒
  if (currentMillis - previousMillis >= INTERVAL) {        // 距離上次,已經過了足夠的時間嗎?
    previousMillis = currentMillis;                        // 記下這次的時間
    ledOn = !ledOn;                                        // 切換狀態
    if (ledOn) {
      digitalWrite(LED_PIN, HIGH);
    } else {
      digitalWrite(LED_PIN, LOW);
    }
  }
  // 這裡沒有 delay:loop() 會飛快地一直重複,有空就去做別的事
}
這一行
它在做什麼
unsigned long previousMillis = 0;
記「上次切換是什麼時候」。寫在函式外面，值才會一直保留。
unsigned long currentMillis = millis();
看一眼時鐘：現在是開機後第幾毫秒。
currentMillis - previousMillis >= INTERVAL
距離上次已經過了 500 毫秒嗎？
previousMillis = currentMillis;
到了：把「上次」更新成現在。
ledOn = !ledOn;
切換狀態(第 7 篇學過 !)。
你會看到紅燈每 0.5 秒切換一次（亮 0.5 秒、滅 0.5 秒），和 delay 版看起來一樣。差別在程式沒有在睡覺。

寫法二：兩件事同時進行

紅燈自己閃、按鈕控制黃燈
// 第 15 篇(寫法二):兩件事同時進行——LED1 自己閃,按鈕控制 LED2
const int BUTTON_PIN = 2;
const int LED1_PIN = 8;
const int LED2_PIN = 9;

const unsigned long BLINK_INTERVAL = {interval};
unsigned long previousMillis = 0;
bool led1On = false;

const unsigned long DEBOUNCE = 30;      // 去彈跳時間(毫秒)
int lastReading = HIGH;                 // 上一次讀到的按鈕狀態
int buttonState = HIGH;                 // 穩定後的按鈕狀態
unsigned long lastChange = 0;           // 按鈕讀值上次變化的時間
bool led2On = false;

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(LED1_PIN, OUTPUT);
  pinMode(LED2_PIN, OUTPUT);
}

void loop() {
  unsigned long now = millis();

  // ---- 工作 1:LED1 每 BLINK_INTERVAL 毫秒切換一次 ----
  if (now - previousMillis >= BLINK_INTERVAL) {
    previousMillis = now;
    led1On = !led1On;
    if (led1On) {
      digitalWrite(LED1_PIN, HIGH);
    } else {
      digitalWrite(LED1_PIN, LOW);
    }
  }

  // ---- 工作 2:按鈕按一下,LED2 切換(不卡住的去彈跳)----
  int reading = digitalRead(BUTTON_PIN);
  if (reading != lastReading) {          // 讀值變了:重新計時,先別相信它
    lastChange = now;
  }
  if (now - lastChange > DEBOUNCE) {     // 讀值已經穩定超過 30 毫秒
    if (reading != buttonState) {        // 而且和上次確認的狀態不同
      buttonState = reading;
      if (buttonState == LOW) {          // 變成 LOW:按下
        led2On = !led2On;
        if (led2On) {
          digitalWrite(LED2_PIN, HIGH);
        } else {
          digitalWrite(LED2_PIN, LOW);
        }
      }
    }
  }
  lastReading = reading;
}
這一行
它在做什麼
// ---- 工作 1 ---- / // ---- 工作 2 ----
把 loop() 分成幾個互不干擾的工作。每一個工作快速檢查一下「該不該做」，不該做就立刻跳過。
if (reading != lastReading) { lastChange = now; }
按鈕讀值一變，就記下時間。
if (now - lastChange > DEBOUNCE)
讀值穩定超過 30 毫秒，才相信它。這是第 7 篇去彈跳的「不卡住」版本：不再用 delay,而是用時間差判斷。
buttonState 與 lastReading
lastReading 是上次讀到的，buttonState 是穩定後確認的狀態。兩者分開，才能分辨「真的按下」與「抖動」。
你會看到紅燈照樣每 0.5 秒一次規律地閃，同時按一下按鈕，黃燈立刻切換，不論你什麼時候按，都不會漏。按住不放也不影響紅燈。

對照：同樣的事用 delay 寫

看看 delay 版（它會漏掉按鈕）
對照組：delay 版
// 對照組:用 delay() 寫的同一件事(會漏掉按鈕!)
const int BUTTON_PIN = 2;
const int LED1_PIN = 8;
const int LED2_PIN = 9;
bool led2On = false;

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(LED1_PIN, OUTPUT);
  pinMode(LED2_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED1_PIN, HIGH);
  delay(500);                        // 睡 0.5 秒:這段時間完全看不到按鈕
  digitalWrite(LED1_PIN, LOW);
  delay(500);                        // 再睡 0.5 秒
  if (digitalRead(BUTTON_PIN) == LOW) {   // 每 1 秒才看一次按鈕
    led2On = !led2On;
    if (led2On) {
      digitalWrite(LED2_PIN, HIGH);
    } else {
      digitalWrite(LED2_PIN, LOW);
    }
  }
}

這支程式每一輪 loop() 要 1 秒，而且只在最後才看一次按鈕。你在紅燈閃的任何時刻短按按鈕，它多半「醒來」時你已經放開，按鈕就被漏掉了（上面的互動示範可以看到）。

常見卡關

LED 完全不閃，或閃爍的間隔不對
  1. previousMillis 是不是寫在函式外面(放進 loop() 裡每輪都會重設成 0)。
  2. 變數是不是 unsigned long,不是 int。
  3. 比較用的是減法。
  4. 有沒有不小心留下 delay()。
按鈕有時候沒反應

檢查 loop() 裡有沒有任何地方還在用 delay(),或是某個工作花太久（例如一次印很多 Serial 資料）。每一輪 loop() 都要很快跑完。

按一下，黃燈切換了兩次（又變回去）

去彈跳沒做好。確認 DEBOUNCE 不是 0，而且判斷的是穩定之後的狀態。

跑了很久之後怪怪的

如果你的 millis() 結果用了 int 或 long（有號），大約 32 秒或 24 天後會溢位出問題。改成 unsigned long,並用減法比較。
