用聲音量距離：越近，蜂鳴器嗶得越快

認識 HC-SR04:Trig 送出脈衝、Echo 回報時間，用 pulseIn 量時間再換算成公分；最後做出越近越快的倒車雷達雛形。

TL;DR Trig 送 10 微秒脈衝 → Echo 的 HIGH 長度 = 聲音來回時間。pulseIn() 量時間，距離(cm) = 時間(µs) × 0.0343 ÷ 2。把量測包成自己的函式，用 map 與 constrain 決定嗶聲間隔。

用聲音量距離：像蝙蝠一樣

HC-SR04 怎麼量

  1. Arduino 在 Trig 腳送出一個 10 微秒的 HIGH 脈衝，告訴模組「開始量」。
  2. 模組發出 8 個 40 kHz 的超音波（人耳聽不到），碰到物體會反彈回來。
  3. 模組把 Echo 腳拉成 HIGH，直到收到回波才放下。HIGH 持續的時間，就是聲音來回的時間。
  4. Arduino 用 pulseIn() 量這段 HIGH 有多長，再用聲速換算成距離。

    從時間換算成距離

    聲速約 343 公尺/秒 = 0.0343 公分/微秒。聲音來回走了兩倍距離，所以：
    距離（公分）= 時間（微秒）× 0.0343 ÷ 2（也可簡化成 ÷ 58）

    拖拖看，距離和回波時間的關係：

      程式一：量距離並印出來

      HC-SR04：印出距離
      // 第 11 篇:量距離,印在 Serial Monitor
const int TRIG_PIN = 9;      // Trig:Arduino 送出觸發脈衝
const int ECHO_PIN = 10;     // Echo:接收回波時間

void setup() {
  Serial.begin(9600);
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
}

void loop() {
  digitalWrite(TRIG_PIN, LOW);       // 先確保是 LOW,等 2 微秒
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);      // 送出 10 微秒的 HIGH,告訴模組「開始量」
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);

  long duration = pulseIn(ECHO_PIN, HIGH, 30000);   // 量 Echo 維持 HIGH 的時間(微秒),最多等 30 毫秒

  if (duration == 0) {               // 0 表示等不到回波
    Serial.println("out of range");
  } else {
    float distance = duration * 0.0343 / 2;         // 聲速 0.0343 公分/微秒;來回要除以 2
    Serial.print(distance, 1);
    Serial.println(" cm");
  }
  delay({gap});
}
      這一行
      它在做什麼
      delayMicroseconds(10);
      暫停 10 微秒（1 毫秒 = 1000 微秒）。delay 的單位是毫秒，delayMicroseconds 是微秒，不要弄混。
      pulseIn(ECHO_PIN, HIGH, 30000)
      量脈衝長度：等 Echo 變成 HIGH，量它維持多久（微秒）。第三個參數是最多等 30000 微秒（30 毫秒），等不到就回傳 0，不會卡死。
      long duration
      long 是能放更大整數的變數(比 int 大很多)。時間的微秒數可能超過 int 的上限，所以用 long。
      duration * 0.0343 / 2
      換算成公分。有小數點的 0.0343，結果就會是 float。
      Serial.print(distance, 1);
      第二個參數 1 表示印小數點後 1 位（第 8 篇學過）。
      你會看到Serial Monitor(baud 9600)每 0.5 秒印一行距離，例如 23.4 cm。拿手或書本在模組前面前後移動，數字跟著變。前面沒有東西或太遠時，印 out of range。
      小技巧先用一本書（硬、平面）正對模組當目標，用尺量實際距離，和 Serial Monitor 比對。誤差在 1 公分左右是正常的。

      程式二：倒車雷達雛形

      把量距離包成一個自己定義的函式 readDistanceCm(),主程式就很好讀。距離越近，蜂鳴器嗶得越快。

      越近越密集的嗶聲
      // 第 11 篇:倒車雷達雛形——越近,嗶得越快
const int TRIG_PIN = 9;
const int ECHO_PIN = 10;
const int BUZZER_PIN = 12;

float readDistanceCm() {              // 自己定義的函式:量一次距離,回傳公分;量不到回傳 -1
  digitalWrite(TRIG_PIN, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG_PIN, HIGH);
  delayMicroseconds(10);
  digitalWrite(TRIG_PIN, LOW);
  long duration = pulseIn(ECHO_PIN, HIGH, 30000);
  if (duration == 0) {
    return -1;
  }
  return duration * 0.0343 / 2;
}

void setup() {
  pinMode(TRIG_PIN, OUTPUT);
  pinMode(ECHO_PIN, INPUT);
  pinMode(BUZZER_PIN, OUTPUT);
}

void loop() {
  float d = readDistanceCm();
  if (d > 0 && d < {far}) {                         // 在範圍內才響
    int gap = map((int)d, 5, {far}, 50, 500);       // 距離 5 → 間隔 50 毫秒;距離 {far} → 間隔 500 毫秒
    gap = constrain(gap, 50, 500);                  // 限制在 50–500 之間
    digitalWrite(BUZZER_PIN, HIGH);
    delay(30);                                      // 嗶 30 毫秒
    digitalWrite(BUZZER_PIN, LOW);
    delay(gap);
  } else {
    delay(100);                                     // 太遠或量不到:不響
  }
}
      這一行
      它在做什麼
      float readDistanceCm() { … }
      會回傳值的函式：前面的 float 是回傳的資料型態。函式裡用 return 把結果交出去。量不到就回傳 -1。
      map((int)d, 5, {far}, 50, 500)
      把「距離 5–{far} 公分」對應成「間隔 50–500 毫秒」。(int)d 把小數轉成整數(map 只收整數，第 9 篇提過)。
      constrain(gap, 50, 500);
      限制範圍：小於 50 就當 50，大於 500 就當 500。避免距離不到 5 公分時間隔變負數。
      d > 0 && d < {far}
      量得到（> 0），而且在範圍內才響(第 10 篇學過 &&)。
      你會看到手從遠處靠近：先是慢慢嗶、嗶、嗶，越近越密，最後幾乎連成一片；拿開或超出範圍，就安靜。
      先記著這段程式每次量測與 delay 時，Arduino 都在等。第 15 篇的 millis() 會教你不卡住的做法，讓第 18 篇的綜合專案可以同時顯示距離。

      改改看

      挑戰
      怎麼改
      你會看到
      改靈敏度
      「幾公分以內才響」改 30
      只有很近時才響。
      距離顯示更精確
      程式一的 Serial.print(distance, 1) 改 2
      小數點後兩位，數字跳動更明顯（但不代表更準）。
      用 LED 代替蜂鳴器
      把蜂鳴器換成第 3 篇的 LED（接 12 號腳），程式不用改
      越近閃越快。

      常見卡關

      一直印 out of range（量不到）
      1. Trig 與 Echo 接反：Trig 要接 9 號腳（輸出），Echo 接 10 號腳。
      2. VCC 或 GND 沒接好：模組沒電就沒有回波。用手摸模組是否微熱（小心別壓到針腳）。
      3. 前面沒有東西、或東西太斜、太軟：換成一本書正對模組。
      4. 程式與接線的腳位不一致。
      距離一直是固定的怪數字

      可能是 Echo 腳浮接，或針腳沒插好。用力按一下模組、確認四隻針腳都在孔裡，再重新上傳。

      數字亂跳很大

      聲音可能反射到旁邊的牆或桌面。把目標放在正前方、周圍淨空；也可以連續量幾次取平均（之後的進階做法）。

      蜂鳴器一直響或完全不響

      檢查蜂鳴器的 + 腳方向與 12 號腳的橘線；程式二的 BUZZER_PIN 要是 12；蜂鳴器是主動式。

      Serial Monitor 空白

      baud 要選 9600（第 8 篇）；有沒有開 Serial Monitor；程式一有 Serial.begin(9600),程式二沒有（它只用蜂鳴器）。
