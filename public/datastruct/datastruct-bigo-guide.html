C++ 演算法 · 第 2 篇 · 複雜度與 Big‑O

資料變多時會慢多少？數操作次數就知道

Big‑O 不量秒數，而是看操作次數隨資料量 n 怎麼成長。這一篇用動畫數一數，再拖動滑桿看六種成長的差距。

TL;DR 單層迴圈 O(n)，雙層迴圈 O(n²)，每次砍一半 O(log n)。化簡只留成長最快的一項、去掉係數。n 變 2 倍時，O(n²) 會慢 4 倍，O(2ⁿ) 很快就算不完。
先備：會寫 for 迴圈。預估 10 分鐘。難度：入門。

不用計時，改成「數步驟」

為什麼不直接量幾秒？

同一段程式，換一台電腦、換一個編譯選項，秒數就不一樣。我們想知道的是更根本的問題：資料變多的時候，程式會慢多少？

所以改成「數操作次數」：資料量 n 變成 2 倍、10 倍時，操作次數怎麼成長？這個成長的樣子，用 Big‑O 記號來描述。

五個名詞

名詞
白話說明
n（輸入規模）
資料的量，例如 vector 的元素個數。
操作次數
程式主要的步驟做了幾次，例如比較、搬動、加法。
時間複雜度
操作次數如何隨 n 成長。
空間複雜度
額外用的記憶體如何隨 n 成長。
Big‑O，O(…)
描述成長趨勢的記號。O(n) 唸作「order n」，意思是「大致和 n 成正比」。

動手玩：數一數操作次數

選一種迴圈、調整 n，一步一步看操作次數怎麼累積。程式碼裡寫 n = 8；改 n 時，把它想成改那一行。

  1. 選「單層迴圈」，n = 5：次數和 n 的關係？
  2. 選「雙層迴圈」，n = 4，再改成 n = 8：次數變成幾倍？
  3. 選「每次砍一半」，n = 16 再改成 n = 32：多了幾次？
main.cpp
#include <iostream>

int main() {
    int n = 8;
    int single = 0;
    for (int i = 0; i < n; ++i) {
        ++single;                            // 單層迴圈:做 n 次
    }

    int nested = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            ++nested;                        // 雙層迴圈:做 n * n 次
        }
    }

    int halving = 0;
    int m = n;
    while (m > 1) {
        m /= 2;
        ++halving;                           // 每次砍一半:大約 log2(n) 次
    }

    std::cout << single << " " << nested << " " << halving << "\n";
}
執行結果（n = 8：單層、雙層、砍一半）
8 64 3
你會看到n = 8 時是 8、64、3。單層是 n，雙層是 n × n，每次砍一半只要 log₂ n 次（8 → 4 → 2 → 1，共 3 次）。

拖拉 n，看六種成長的差距

這是最常見的六種成長。把 n 從小拉到大，看哪幾條線衝上天、哪幾條幾乎貼地。

猜猜看：這一步會發生什麼？

三條化簡規則

數出來的次數常常是 3n² + 5n + 2 這種樣子。Big‑O 只關心「n 很大時，誰最大」，所以這樣化簡：

規則
例子
原因
只留成長最快的那一項
n² + n → O(n²)
n = 1000 時，n² 是 100 萬，n 只有 1000，可以忽略。
去掉前面的係數
3n → O(n)
係數取決於電腦與寫法；我們看的是成長的形狀。
不同的輸入用不同的字母
掃 a 個再掃 b 個 → O(a + b)
兩個 vector 的大小互不相干，不要都寫成 n。
一個接一個，還是一個套一個？兩個迴圈一個接一個（各 n 次）是 n + n = 2n，仍是 O(n)；一個套在另一個裡面是 n × n，變成 O(n²)。看迴圈怎麼擺，比看有幾個更重要。

空間複雜度

同樣的算法，看「額外」用了多少記憶體。只多用幾個變數是 O(1)；另外複製一份長度 n 的 vector 是 O(n)。後面學到遞迴、雜湊表時，空間也會成為取捨的一部分。

初學者最常卡住的三個地方

O(n) 一定比 O(n²) 快嗎？

n 很大時是的，n 很小時不一定。Big‑O 省略了係數，所以 n = 5 時，一個寫得很囉嗦的 O(n) 可能輸給寫得簡潔的 O(n²)。它回答的是「資料變大時，誰撐得住」。

兩段程式都是 O(n)，速度就一樣嗎？

不一定。Big‑O 只描述成長的形狀，不管每一步多貴。都是 O(n) 的兩段程式，一個每圈做 1 次加法、一個每圈做 100 次運算，實際速度差很多。想比較真實速度，要實際量測。

O(n + n) 為什麼會寫成 O(n)？

去掉係數的規則：2n 和 n 成長的形狀一樣，都是「資料多一倍，時間多一倍」。所以寫成 O(n)。

動手寫（兩題）

第 1 題：判斷時間複雜度

下面的 countEven 時間是 O(?)？想好再看答案。

main.cpp
#include <iostream>
#include <vector>

// 這個函式的時間是 O(?)。先想,再展開答案。
int countEven(const std::vector<int>& v) {
    int count = 0;
    for (int x : v) {
        if (x % 2 == 0) {
            ++count;
        }
    }
    return count;
}

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5, 6};
    std::cout << countEven(v) << "\n";
}
參考答案

O(n)：迴圈每個元素看一次，每次做固定的幾步（取餘數、比較、可能加 1），總共 n 圈。

執行結果
3

第 2 題：寫出函式，再判斷複雜度

完成 hasPairSum（最直覺的寫法就好），輸出要是 1 0。然後想想：它是 O(?)?

main.cpp
#include <iostream>
#include <vector>

// 回傳 v 裡有沒有「兩個不同位置的元素相加等於 target」。
// 先用最直覺的寫法完成它,再回答:時間是 O(?)
bool hasPairSum(const std::vector<int>& v, int target) {
    (void)v;
    (void)target;
    return false;
}

int main() {
    std::vector<int> v = {3, 8, 1, 9};
    std::cout << hasPairSum(v, 10) << " " << hasPairSum(v, 100) << "\n";   // 預期輸出 1 0
}
參考答案

檢查所有兩兩配對：外層 i 跑 n 圈，內層 j 從 i + 1 跑到尾，大約 n²/2 次，去掉係數是 O(n²)。第 10 篇學雜湊表之後，可以改成 O(n)。

完整答案
#include <iostream>
#include <vector>

bool hasPairSum(const std::vector<int>& v, int target) {
    int n = static_cast<int>(v.size());
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (v[i] + v[j] == target) {
                return true;
            }
        }
    }
    return false;
}

int main() {
    std::vector<int> v = {3, 8, 1, 9};
    std::cout << hasPairSum(v, 10) << " " << hasPairSum(v, 100) << "\n";
}
執行結果
1 0
