把算過的答案記下來：一格一格填表

動態規劃就是「小問題的答案存進表、大問題直接查表」。這一篇用填表動畫看費氏數列、爬樓梯與 0/1 背包，並點格子看每一格依賴誰。

TL;DR DP 適用於「能拆成小問題、且小問題會重複」。做法是定義 dp 的意思、寫出關係式、填起始值、照順序填表。fib(30) 遞迴約 270 萬次呼叫，DP 只要 30 步。0/1 背包的表有 (n+1) × (W+1) 格，時間 O(n × W)。

直覺：別把同一件事算很多次

第 7 篇的 fib，慢在哪裡？

遞迴版 fib(30) 會呼叫將近 270 萬次，因為 fib(28)、fib(27) 這些小問題被一再重複計算。動態規劃（dynamic programming，簡稱 DP）的想法很簡單：算過的答案記下來，下次直接查表。

能用 DP 的問題有兩個特徵：大問題可以拆成小問題，而且很多小問題是重複的。

main.cpp
#include <iostream>
#include <vector>

long long calls = 0;

long long fibSlow(int n) {
    ++calls;
    if (n < 2) {
        return n;
    }
    return fibSlow(n - 1) + fibSlow(n - 2);
}

long long fibMemo(int n, std::vector<long long>& memo) {
    ++calls;
    if (n < 2) {
        return n;
    }
    if (memo[n] != -1) {
        return memo[n];
    }
    memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}

int main() {
    const int n = 30;
    calls = 0;
    long long a = fibSlow(n);
    std::cout << "沒有記憶:fib(" << n << ") = " << a << ",呼叫 " << calls << " 次\n";
    calls = 0;
    std::vector<long long> memo(n + 1, -1);
    long long b = fibMemo(n, memo);
    std::cout << "有記憶:  fib(" << n << ") = " << b << ",呼叫 " << calls << " 次\n";
}
執行結果：同一個 fib(30)
沒有記憶:fib(30) = 832040,呼叫 2692537 次
有記憶:  fib(30) = 832040,呼叫 59 次

動手玩：一格一格填表

選問題，按「執行」。橘色是正在填的格子，綠色是它依賴的格子（要先填好）。費氏與爬樓梯是一排格子，0/1 背包是一張二維的表（物品：重 1 值 1、重 3 值 4、重 4 值 5、重 5 值 7）。

  1. 先跑費氏 n=8，看每一格是不是只用到前面兩格。
  2. 再跑爬樓梯 n=8：算式一樣，但起始值是 dp[0] = 1，答案不同。
  3. 跑 0/1 背包（容量 7）：每一格都在比「不拿」和「拿」哪個價值大。
  4. 把背包容量改成 3、5、10 看看答案怎麼變。

猜猜看：爬樓梯有幾種方法？

一次可以爬 1 階或 2 階，爬到第 4 階有幾種不同的爬法？

選一個做法，看看對不對。

點格子看依賴（背包，容量 7）

這是填完的背包表。點任何一格，看它是從哪些格子算出來的：每一格最多只依賴上一列的兩格。

完整程式：三個 DP

三題的骨架一樣：先建 dp 表、填起始值、照順序用前面的格子算出後面的。注意 dp 要用 long long，費氏數列長大得很快。

main.cpp
#include <algorithm>
#include <iostream>
#include <vector>

long long fib(int n) {
    std::vector<long long> dp(n + 2);
    dp[0] = 0;
    dp[1] = 1;
    for (int i = 2; i <= n; ++i) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}

long long climbStairs(int n) {
    std::vector<long long> dp(n + 2);
    dp[0] = 1;
    dp[1] = 1;
    for (int i = 2; i <= n; ++i) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}

int knapsack(const std::vector<int>& wt, const std::vector<int>& val, int cap) {
    int n = static_cast<int>(wt.size());
    std::vector<std::vector<int>> dp(n + 1, std::vector<int>(cap + 1, 0));
    for (int i = 1; i <= n; ++i) {
        for (int w = 0; w <= cap; ++w) {
            dp[i][w] = dp[i - 1][w];
            if (w >= wt[i - 1]) {
                dp[i][w] = std::max(dp[i][w], dp[i - 1][w - wt[i - 1]] + val[i - 1]);
            }
        }
    }
    return dp[n][cap];
}

int main() {
    std::cout << "fib(10) = " << fib(10) << "\n";
    std::cout << "爬 5 階樓梯有 " << climbStairs(5) << " 種方法\n";
    std::cout << "背包最大價值 = " << knapsack({1, 3, 4, 5}, {1, 4, 5, 7}, 7) << "\n";
}
執行結果
fib(10) = 55
爬 5 階樓梯有 8 種方法
背包最大價值 = 9

g++ -std=c++17 -Wall -Wextra -o main main.cpp
./main
背包那一行在做什麼dp[i][w] 是「只考慮前 i 個物品、容量 w」的最大價值。物品 i 要嘛不拿（= 上面那格），要嘛拿（= 容量少掉它的重量那格 + 它的價值），取較大的。這就是 0/1 的意思：每個物品只能拿 0 個或 1 個。

複雜度小表

DP 的時間大多等於「表有幾格 × 每格要看幾個格子」。

DP

遞迴 O(2ⁿ)(fib(30) 約 270 萬次)
O(n)
爬樓梯
遞迴 O(2ⁿ)
O(n)

O(n × W)，表有 (n+1) × (W+1) 格

一句話：DP 用空間換時間，把指數時間變成「表的大小」。

初學者最常卡住的四個地方

起始值忘了填或填錯

填表是從已知的小答案長出來的。費氏的 dp[0]、dp[1]，爬樓梯的 dp[0] = 1，背包的第 0 列，少一個後面全部會錯。vector 要開 n + 2 格，避免 n = 0 或 1 時讀到範圍外。

dp 到底代表什麼，自己講不清楚

動手寫之前，先用一句話寫下 dp[i]（或 dp[i][w]）的意思，例如「只考慮前 i 個物品、容量 w 的最大價值」。意思不清楚，關係式一定寫不對。

填表順序反了

算某一格時，它依賴的格子必須已經填好。費氏由小到大填；背包一列一列填，因為每格只依賴上一列。順序錯了，讀到的是沒填的 0。

背包要用貪婪（挑最划算的）

0/1 背包用「價值除以重量最高的先拿」會得到錯的答案（例如容量不夠放整個物品，但差一點）。這種「拿了不能反悔、也不能拿一半」的問題要靠 DP 比較所有取捨。下一篇會看貪婪什麼時候可以用、什麼時候不行。

動手寫（兩題）

第 1 題：一次爬 1、2 或 3 階

把爬樓梯改成一次可以爬 1、2 或 3 階。輸出應該是 7 13 1。

main.cpp
#include <iostream>
#include <vector>

// 爬樓梯變化:一次可以爬 1、2 或 3 階,爬到第 n 階有幾種方法?(n >= 0)
// 提示:dp[i] = dp[i-1] + dp[i-2] + dp[i-3];要小心 i < 3 時不能讀到負的位置。
long long ways(int n) {
    (void)n;
    return 0;
}

int main() {
    std::cout << ways(4) << " " << ways(5) << " " << ways(0) << "\n";   // 預期輸出 7 13 1
}
參考答案

最後一步有三種可能，所以 dp[i] 是前三格相加。用內層迴圈走 1~3 步，並檢查 i - step >= 0，就不會讀到負的位置，n = 0 也不用特判。

完整答案
#include <iostream>
#include <vector>

long long ways(int n) {
    std::vector<long long> dp(n + 3, 0);
    dp[0] = 1;
    for (int i = 1; i <= n; ++i) {
        for (int step = 1; step <= 3; ++step) {
            if (i - step >= 0) {
                dp[i] += dp[i - step];
            }
        }
    }
    return dp[n];
}

int main() {
    std::cout << ways(4) << " " << ways(5) << " " << ways(0) << "\n";
}
執行結果
7 13 1

第 2 題：最少硬幣數

用最少的硬幣湊出 amount，每種硬幣無限多枚，湊不出來回傳 -1。輸出應該是 2 -1 3。（{1,3,4} 湊 6 最少 2 枚，3 + 3。）

main.cpp
#include <iostream>
#include <vector>

const int INF = 1000000000;

// 用最少的硬幣湊出 amount;湊不出來回傳 -1。每種硬幣可以用無限多枚。
// 提示:dp[a] = 湊出金額 a 最少要幾枚;dp[a] = min(dp[a - c] + 1),對每種硬幣 c(a >= c 且 dp[a - c] 不是 INF)。
int coinChange(const std::vector<int>& coins, int amount) {
    (void)coins;
    (void)amount;
    return -2;
}

int main() {
    std::cout << coinChange({1, 3, 4}, 6) << " " << coinChange({2}, 3) << " " << coinChange({1, 2, 5}, 11) << "\n";   // 預期輸出 2 -1 3
}
參考答案

dp[a] 是湊出金額 a 最少要幾枚。對每種硬幣 c：如果 a >= c 而且 dp[a - c] 湊得出來，就試著用 dp[a - c] + 1 更新。O(amount × 硬幣種類)。下一篇會看到，這題用貪婪（先拿最大的）有時會錯。

完整答案
#include <algorithm>
#include <iostream>
#include <vector>

const int INF = 1000000000;

int coinChange(const std::vector<int>& coins, int amount) {
    std::vector<int> dp(amount + 1, INF);
    dp[0] = 0;
    for (int a = 1; a <= amount; ++a) {
        for (int c : coins) {
            if (a >= c && dp[a - c] != INF) {
                dp[a] = std::min(dp[a], dp[a - c] + 1);
            }
        }
    }
    return dp[amount] == INF ? -1 : dp[amount];
}

int main() {
    std::cout << coinChange({1, 3, 4}, 6) << " " << coinChange({2}, 3) << " " << coinChange({1, 2, 5}, 11) << "\n";
}
執行結果
2 -1 3
