遞迴就是把問題縮小，直到小到能直接回答

函式在裡面呼叫自己。這一篇用呼叫堆疊與呼叫樹的動畫，看階乘與費氏數列怎麼一層層展開、再一層層回來，也看為什麼天真的 fib 會慢。

TL;DR 遞迴三要素：基底條件（何時停）、縮小問題、相信子呼叫。每次呼叫佔呼叫堆疊一層，太深會爆；天真的 fib 因為重複計算是指數時間。

遞迴：把大問題變成「同樣形狀的小問題」

想像一組俄羅斯娃娃

要數有幾個娃娃：打開最外面一個，剩下的是「一組比較小的娃娃」，而數它的方法跟原本一樣。一直打開，直到打開後裡面是空的，就知道數完了。

寫成程式就是：函式在裡面呼叫自己，每次處理的問題都比上一次小，小到不能再小時停下來。

寫遞迴只要記住三件事

要素
說明
基底條件
問題小到可以直接回答的時候（例如 n == 0）。沒有它就會無限呼叫下去。
縮小問題
每次呼叫自己時，參數要更靠近基底條件（例如 n - 1）。
相信子呼叫
寫的時候假設 f(n - 1) 已經算對了，你只負責「用它的答案算出 f(n)」。

先看最簡單的例子，倒數計時：

main.cpp
#include <iostream>

void countdown(int n) {
    if (n == 0) {
        std::cout << "liftoff\n";             // 基底條件:不再呼叫自己
        return;
    }
    std::cout << n << " ";
    countdown(n - 1);                        // 呼叫自己,但問題變小了
}

int main() {
    countdown(3);
}
執行結果
3 2 1 liftoff
你會看到countdown(3) 印 3，呼叫 countdown(2)，印 2，呼叫 countdown(1)，印 1，呼叫 countdown(0)，碰到基底條件印出 liftoff 後一路返回。

動手玩：看呼叫堆疊與呼叫樹

每呼叫一次函式，上方的呼叫堆疊就多一層（和第 5 篇的 stack 一樣，後進先出）；下方的呼叫樹記錄誰呼叫了誰。節點旁邊的「=數字」是它回傳的結果。

  1. 選 fact、n = 4：看呼叫一路往下到基底條件，再一路往回乘出答案。
  2. 選 fib、n = 4，再改成 n = 6：樹長成什麼樣？
  3. 注意虛線框的節點：它們是「已經算過的 fib(k) 又被重新算一遍」。

猜猜看：這一步會發生什麼？

fact(4) 一共會呼叫 fact 這個函式幾次（包含最外層那次）？

選一個做法，看看對不對。

完整程式：階乘與費氏數列

fact(n) = n × (n − 1) × … × 1;fib(n) 每一項是前兩項的和（0, 1, 1, 2, 3, 5, 8…）。兩個函式都符合「三要素」。

main.cpp
#include <iostream>

int fact(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * fact(n - 1);
}

int fib(int n) {
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main() {
    std::cout << fact(5) << " " << fib(6) << "\n";
}
執行結果(fact(5)、fib(6))
120 8

記得這個順序：fact(5) 先往下呼叫到 fact(1)（基底條件），回傳時才開始乘。每一層都在等下一層的答案，所以呼叫堆疊上同時有很多層。

為什麼 fib 會慢？重複計算

回頭看 fib(6) 的呼叫樹：fib(3) 出現了好幾次，每次都從頭算。n 一大，重複的次數爆炸成長。下面是用真正的程式數出來的呼叫次數：

main.cpp
#include <iostream>

long long calls = 0;

int fib(int n) {
    ++calls;
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main() {
    for (int n : {10, 20, 30}) {
        calls = 0;
        int result = fib(n);
        std::cout << "fib(" << n << ") = " << result << ", calls = " << calls << "\n";
    }
}
執行結果（呼叫次數）
fib(10) = 55, calls = 177
fib(20) = 6765, calls = 21891
fib(30) = 832040, calls = 2692537
n 每加 10，次數約變成 120 倍這是指數成長(大約 O(1.6ⁿ)，常簡化說成 O(2ⁿ))。n = 50 時，你的電腦可能算好幾個小時。第 16 篇「動態規劃」會教你把算過的結果記下來，讓 fib 變成 O(n)。

遞迴的第二個例子：二分搜尋

上一篇的二分搜尋也能寫成遞迴：每次只留下一半，「在剩下一半裡搜尋」就是一個一模一樣、但更小的問題。這裡有兩個基底條件：範圍空了（沒找到）、找到了。

main.cpp
#include <iostream>
#include <vector>

int search(const std::vector<int>& v, int target, int lo, int hi) {
    if (lo > hi) {
        return -1;                           // 基底條件 1:範圍空了
    }
    int mid = lo + (hi - lo) / 2;
    if (v[mid] == target) {
        return mid;                          // 基底條件 2:找到了
    }
    if (v[mid] < target) {
        return search(v, target, mid + 1, hi);   // 只剩右半邊
    }
    return search(v, target, lo, mid - 1);       // 只剩左半邊
}

int main() {
    std::vector<int> v = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
    int n = static_cast<int>(v.size());
    std::cout << search(v, 23, 0, n - 1) << " " << search(v, 7, 0, n - 1) << "\n";
}
執行結果
5 -1

複雜度小表：時間與呼叫堆疊

遞迴的「空間」要把呼叫堆疊的深度算進去：每一層都佔一點記憶體。

函式
時間
空間（堆疊深度）
fact(n)
O(n)
O(n)：最深有 n 層
fib(n)（上面的寫法）
指數，約 O(2ⁿ)
O(n)：最深是從 n 一路減到 1
遞迴二分搜尋
O(log n)
O(log n)：每層砍一半

初學者最常卡住的三個地方

忘了寫基底條件：無限遞迴

少了基底條件，函式永遠不會停，一直呼叫下去，直到呼叫堆疊用光、程式當掉。連編譯器都看得出來，會警告你：

錯誤示範（不要執行）
// 錯誤示範:少了基底條件。編譯器會警告,執行會一直往下呼叫直到當掉
int badFact(int n) {
    return n * badFact(n - 1);
}
g++ -Wall 的警告（實際輸出）
warning: infinite recursion detected [-Winfinite-recursion]
遞迴太深：呼叫堆疊爆掉（stack overflow）

每一層呼叫都要佔一小塊記憶體。一般電腦大約幾萬到幾十萬層就會用完，所以 sumTo(1000000) 這種寫法很可能直接當掉。層數可能很深的時候，改用迴圈。

遞迴一定比迴圈好嗎？

不一定。像 fact 用迴圈寫更省空間。遞迴的優勢是：遇到「問題裡面有同樣形狀的小問題」時（樹的走訪、排列組合、分治法），寫起來特別自然。後面的二元樹、合併排序、回溯都會用到。

動手演練：確認你真的懂了

動手寫（兩題）

第 1 題：補上基底條件

sumTo(n) 要回傳 1 + 2 + … + n。目前缺基底條件，執行會當掉。補上它，輸出應該是 15 0。

main.cpp
#include <iostream>

// 回傳 1 + 2 + ... + n
int sumTo(int n) {
    // 在這裡補上基底條件:n 是 0 的時候,總和是多少?
    return n + sumTo(n - 1);
}

int main() {
    std::cout << sumTo(5) << " " << sumTo(0) << "\n";   // 預期輸出 15 0
}
參考答案

n 等於 0 的時候總和是 0，直接回傳。其他情況用 n + sumTo(n - 1)。

完整答案
#include <iostream>

int sumTo(int n) {
    if (n == 0) {
        return 0;
    }
    return n + sumTo(n - 1);
}

int main() {
    std::cout << sumTo(5) << " " << sumTo(0) << "\n";
}
執行結果
15 0

第 2 題：用遞迴寫 power

完成 power(base, exp)。輸出應該是 8 1。想想三要素：基底條件是什麼？怎麼縮小問題？

main.cpp
#include <iostream>

// 回傳 base 的 exp 次方(exp 是 0 或正整數)。用遞迴寫:
// base^exp = base * base^(exp - 1),而 base^0 = 1
int power(int base, int exp) {
    (void)base;
    (void)exp;
    return 0;
}

int main() {
    std::cout << power(2, 3) << " " << power(5, 0) << "\n";   // 預期輸出 8 1
}
參考答案

基底條件：exp == 0 時回傳 1。縮小問題：base × power(base, exp - 1)。時間是 O(exp)。

完整答案
#include <iostream>

int power(int base, int exp) {
    if (exp == 0) {
        return 1;
    }
    return base * power(base, exp - 1);
}

int main() {
    std::cout << power(2, 3) << " " << power(5, 0) << "\n";
}
執行結果
8 1
