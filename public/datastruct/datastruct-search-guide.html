已排序的資料，每次砍一半就能找得又快又準

線性搜尋一個個比，二分搜尋每次排除一半。這一篇用動畫並排看兩種方法的比較次數，體會 O(n) 和 O(log n) 的差距。

TL;DR 線性搜尋 O(n)，不要求排序；二分搜尋 O(log n)，要求已排序，靠 lo/hi/mid 每次砍掉一半。n = 1,000,000 時，最壞只要比約 20 次。

猜數字遊戲：每次猜中間，一次砍掉一半

兩種找法

朋友心裡想 1 到 100 的一個數字。笨方法：從 1 開始一個個猜，最壞要猜 100 次。聰明方法：每次猜中間值 50，朋友只要說「大了」或「小了」，你就能一次排除一半，頂多 7 次就猜中。

前者是線性搜尋，後者是二分搜尋。聰明方法有個前提：數字有大小順序，也就是資料要已排序。

動手玩：線性與二分搜尋逐步比較

完整程式：兩種搜尋

兩個函式都回傳「找到的索引」，找不到回傳 -1。

main.cpp
#include <iostream>
#include <vector>

int linearSearch(const std::vector<int>& v, int target) {
    for (int i = 0; i < static_cast<int>(v.size()); ++i) {
        if (v[i] == target) {
            return i;
        }
    }
    return -1;
}

int binarySearch(const std::vector<int>& v, int target) {
    int lo = 0;
    int hi = static_cast<int>(v.size()) - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (v[mid] == target) {
            return mid;
        } else if (v[mid] < target) {
            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    return -1;
}

int main() {
    std::vector<int> v = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
    std::cout << linearSearch(v, 23) << " " << binarySearch(v, 23) << "\n";
    std::cout << linearSearch(v, 7) << " " << binarySearch(v, 7) << "\n";
}
執行結果（找 23 與找 7）
5 5
-1 -1
看不懂的地方
說明
lo <= hi
範圍裡還有至少一個元素時才繼續。lo 超過 hi，表示範圍空了，沒找到。
mid = lo + (hi - lo) / 2
取中間。不直接寫 (lo + hi) / 2，是因為資料量很大時 lo + hi 可能超出 int 範圍。
lo = mid + 1 / hi = mid - 1
已經看過 mid 了，所以新範圍要跳過 mid。少了 ±1 可能卡住不動。

實務上：std::find 與 std::binary_search

標準函式庫都有現成的，放在 <algorithm>。回傳的是「迭代器」（指向元素的位置），減去 v.begin() 就是索引。

main.cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
    auto it = std::find(v.begin(), v.end(), 23);                       // 線性搜尋
    std::cout << (it != v.end() ? it - v.begin() : -1) << "\n";
    std::cout << std::binary_search(v.begin(), v.end(), 23) << "\n";   // 二分搜尋:有沒有
    auto lb = std::lower_bound(v.begin(), v.end(), 20);                // 第一個 >= 20 的位置
    std::cout << lb - v.begin() << " " << *lb << "\n";
}
執行結果
5
1
5 23
函式
用途
std::find
線性搜尋，不要求排序；找不到回傳 v.end()。
std::binary_search
二分搜尋，只回答「有沒有」(true/false)；要求已排序。
std::lower_bound
二分搜尋，回傳第一個「大於等於目標」的位置。動手寫第 2 題就是它。

初學者最常卡住的三個地方

對沒排序的資料用二分搜尋，結果是錯的

二分搜尋靠「中間比目標大，所以目標在左邊」這個推論，資料沒排序就不成立。下面的陣列裡明明有 1（索引 3），二分搜尋卻回傳 -1:

main.cpp（節錄 main 之前相同）
#include <iostream>
#include <vector>

int linearSearch(const std::vector<int>& v, int target) {
    for (int i = 0; i < static_cast<int>(v.size()); ++i) {
        if (v[i] == target) {
            return i;
        }
    }
    return -1;
}

int binarySearch(const std::vector<int>& v, int target) {
    int lo = 0;
    int hi = static_cast<int>(v.size()) - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (v[mid] == target) {
            return mid;

            lo = mid + 1;
        } else {
            hi = mid - 1;
        }
    }
    return -1;
}

int main() {
    std::vector<int> v = {5, 2, 9, 1, 7};    // 沒有排序!
    std::cout << binarySearch(v, 1) << " " << linearSearch(v, 1) << "\n";
}
執行結果（二分、線性）
-1 3
寫成 lo = mid，程式卡住不動

如果範圍剩兩個元素，mid 會等於 lo。這時寫 lo = mid 範圍完全沒縮小，迴圈永遠不結束。記得 lo = mid + 1、hi = mid - 1。

(lo + hi) / 2 為什麼有人說不好？

當 lo 和 hi 都很大（接近 int 上限的一半以上）時，相加會溢位變成負數。lo + (hi - lo) / 2 不會。小資料看不出差別，但這是好習慣。

第 2 題：寫出 lowerBound

完成 lowerBound：回傳第一個「大於等於 target」的索引，都比 target 小就回傳 v.size()。輸出應該是 1 3 5 0。

main.cpp
#include <iostream>
#include <vector>

// 在「已排序」的 v 裡,回傳第一個「大於等於 target」的元素的索引;
// 如果每個元素都比 target 小,回傳 v.size()。
int lowerBound(const std::vector<int>& v, int target) {
    int lo = 0;
    int hi = static_cast<int>(v.size());     // 答案可能是 size(),所以 hi 從 size 開始
    // 提示:用 while (lo < hi),mid 的值如果小於 target,答案在右邊;否則 mid 本身也可能是答案
    (void)v;
    (void)target;
    return lo + hi - hi;
}

int main() {
    std::vector<int> v = {1, 3, 3, 5, 8};
    std::cout << lowerBound(v, 3) << " " << lowerBound(v, 4) << " " << lowerBound(v, 9) << " " << lowerBound(v, 0) << "\n";   // 預期輸出 1 3 5 0
}
參考答案

這一版的範圍是 [lo, hi)（hi 取不到）。mid 小於 target，答案在右邊，lo = mid + 1；否則 mid 本身可能就是答案，hi = mid。範圍縮到空，lo 就是答案。時間 O(log n)。

完整答案
#include <iostream>
#include <vector>

int lowerBound(const std::vector<int>& v, int target) {
    int lo = 0;
    int hi = static_cast<int>(v.size());
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (v[mid] < target) {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    return lo;
}

int main() {
    std::vector<int> v = {1, 3, 3, 5, 8};
    std::cout << lowerBound(v, 3) << " " << lowerBound(v, 4) << " " << lowerBound(v, 9) << " " << lowerBound(v, 0) << "\n";
}
執行結果
1 3 5 0
