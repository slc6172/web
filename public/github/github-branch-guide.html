GitHub 入門 · 第 3 篇 · 分支與合併

一件事一個分支,衝突只是 git 在問你留誰的

分支讓你在不弄髒 main 的情況下放心嘗試。這一篇從開分支、合併,一路練到親手製造並解決一次衝突,讓你下次遇到時不再慌張。

TL;DR 用 git switch -c 開分支、在上面 commit、切回 main 用 git merge 合進來。兩邊改了同一行就會衝突:打開檔案留下要的內容、刪掉三種標記、add 再 commit。

分支讓你放心地試

用「草稿本」來想

main 是已經定稿的正本。想試新點子,就另外開一本草稿本(分支):在上面隨便改、隨便 commit,正本完全不受影響。滿意了,再把草稿合併(merge)回正本;不滿意,整本丟掉就好。

所以:一件事一個分支。這也是第 6 篇 Pull Request 的基礎。

六個名詞

名詞
白話說明
branch(分支)
一條獨立的 commit 時間線。建立分支很便宜,幾乎瞬間完成。
HEAD
「你現在站的位置」。git status 第一行 On branch … 就是在告訴你它在哪。
switch
切換到另一條分支。檔案會跟著變成那條分支的樣子。
merge(合併)
把另一條分支的 commit 整合進目前所在的分支。
fast-forward
主線沒有新進度時,merge 只是把指標往前推,不產生新的合併 commit。
conflict(衝突)
兩條分支改了同一個地方,git 無法自己決定留誰的,需要你來選。

照著做:八個步驟

1

先確認你站在哪條分支

動手前先看位置,是避免「改錯地方」的第一個習慣。以下在你練習用的 repo 資料夾裡執行。

git status
git branch
你會看到On branch main;git branch 列出所有本機分支,目前所在的前面有 *。
2

建立並切換到新分支

取一個看得出在做什麼的短名字,不要有空白,用 - 連接。

git switch -c {branch}
git branch
你會看到Switched to a new branch '{branch}';git branch 的 * 移到了新分支上。
小技巧switch -c 的 c 是 create:建立並切過去。只想切換既有分支時不加 -c。舊版 git(低於 2.23)請用 git checkout -b {branch}。
3

在分支上改檔案、commit

跟平常一模一樣。差別只在:這些 commit 現在只屬於這條分支。

echo "新功能草稿" > feature.txt
git add feature.txt
git commit -m "新增 feature.txt"
git log --oneline -n 3
你會看到log 最上面是你剛剛的 commit,後面括號裡寫著 HEAD -> {branch}。
4

切回 main,看見「草稿」不見了

切換分支時,資料夾裡的檔案會跟著換成那條分支的樣子。這是理解分支最直觀的一步。

git switch main
ls
你會看到資料夾裡沒有 feature.txt(Windows 的 Git Bash 用 ls,PowerShell 用 dir)。它沒有消失,只是存在另一條分支上。再切回去就會出現。
5

merge:把分支合進 main

合併的方向很重要:你站在誰身上,就是誰接收別人的成果。要把 feature 合進 main,就要先站在 main。

git switch main
git merge {branch}
git log --oneline -n 3
你會看到因為 main 在分出去之後沒有新進度,出現 Fast-forward,feature.txt 出現在 main。log 裡看不到額外的合併 commit。
小技巧如果 main 之後也有新 commit(像全貌圖那樣),merge 會產生一個新的合併 commit,並請你確認訊息:直接存檔離開即可。
6

故意製造一次衝突(練習用)

與其等衝突自己找上門,不如先在安全的地方遇到它一次。下面讓兩條分支改同一個檔案的同一行。

git switch main
echo "標題:主線版本" > title.txt
git add title.txt
git commit -m "main: 新增 title.txt"
git switch -c feature-title
echo "標題:分支版本" > title.txt
git add title.txt
git commit -m "分支: 改標題"
git switch main
echo "標題:主線再改一次" > title.txt
git add title.txt
git commit -m "main: 再改標題"
git merge feature-title
你會看到CONFLICT (content): Merge conflict in title.txt,並顯示 Automatic merge failed; fix conflicts and then commit the result.。git status 會列出 both modified: title.txt。
小技巧這不是壞掉,是 git 在問你:「兩邊都改了這行,你要哪個?」
7

看懂標記、決定內容、完成合併

git 把兩邊的內容都放進檔案,用三種標記隔開。你的工作是:留下最終要的內容,並把三種標記行整行刪掉。

打開 title.txt 會看到
<<<<<<< HEAD
標題:主線再改一次
=======
標題:分支版本
>>>>>>> feature-title
標記
意思
<<<<<<< HEAD
從這行到 ======= 是「你現在所在分支」(這裡是 main)的內容。
=======
分隔線。
>>>>>>> feature-title
從分隔線到這行是「要合進來的分支」的內容。
  1. 用編輯器打開 title.txt,改成你要的最終內容,例如只留一行 標題:合併後的版本。確認沒有任何 <<<<<<<、=======、>>>>>>> 殘留。
  2. 存檔後,告訴 git 這個檔案解決了,並完成合併。
git add title.txt
git commit -m "解決 title.txt 的衝突"
git log --oneline --graph -n 6
你會看到git log --graph 顯示兩條線匯合成一個合併 commit。
注意標記行一定要刪乾淨。留下 <<<<<<< 就 commit,等於把標記當成檔案內容提交了。
8

刪掉用完的分支

合併完成後,草稿本可以丟了。刪除分支只是刪掉那個名字,commit 已經在 main 裡了。

git branch -d {branch}
git branch -d feature-title
git branch
你會看到Deleted branch {branch};git branch 只剩 main。

初學者最常卡住的五個地方

切換分支時顯示 Your local changes would be overwritten

你有尚未 commit 的修改,而且和目標分支會衝到。二選一:

  1. 先 commit 把它存起來。
  2. 還不想 commit,就暫時收起來:
git stash
git switch 目標分支
# 回來之後再拿出來
git stash pop
衝突解到一半,想全部放棄

合併還沒完成時,可以整個退回合併前的狀態,什麼都不會損失:

git merge --abort
git branch -d 說 “not fully merged”

git 認為這條分支還有 commit 沒進到目前分支。如果你確認內容已經合併(例如在 GitHub 上用 Squash and merge,commit 被壓成新的一個,git 認不出來),可以強制刪除:

git branch -D {branch}
我不知道自己現在在哪條分支

打 git status,第一行就是答案。也可以用 git branch,有 * 的那條。

我在 main 上 commit 了本來該在分支做的事

commit 還在,先在目前位置開一個分支把它存起來。把 main 拉回與遠端一致的做法,在第 6 篇 Pull Request 的常見卡關有完整步驟。

git branch {branch}
