GitHub 入門 · 第 2 篇 · .gitignore 與歷史

先寫 .gitignore,再第一次 commit

新手最早踩到的坑,是把 node_modules 或 .env 一起 commit 上去。這一篇教你用 .gitignore 擋住不該進 repo 的檔案,並用 status、diff、log 看清楚 repo 裡發生了什麼。

TL;DR 不想進 repo 的檔案寫進 .gitignore;但它只管「還沒被追蹤」的檔案。已經 commit 過的密碼,擋不回來,要當作外洩處理。commit 前養成 status 與 diff 看一遍的習慣。

不是每個檔案都該進 repo

用「搬家打包」來想

你搬家時會挑東西裝箱,不會把垃圾、暫時用的雜物、和裝滿密碼的筆記本一起帶走。.gitignore 就是一張「這些不要打包」的清單,git 看到符合的檔案就當作它不存在。

越早寫越好:一旦 commit 過,檔案就進了歷史,事後補規則不會讓它消失(見步驟 5)。

最常見的六類「不該進 repo」

類型
例子

密碼與金鑰
.env、*.pem
一旦上傳,等於公開。這是新手最危險的錯誤(見第 10 篇)。
套件資料夾

體積大、可由設定檔重新安裝,別人 clone 後自己裝就好。

全貌:檔案有四種狀態

新檔案出現時,git 先比對 .gitignore。符合的被忽略;不符合的才進入「未追蹤 → 已暫存 → 已追蹤」這條路。

  1. 1比對規則:新檔案先過 .gitignore 這一關。
  2. 2add:未追蹤的檔案放進暫存區。
  3. 3commit:暫存的內容寫進歷史,成為已追蹤。
  4. !被忽略的檔案不在這條路上,git status 看不到它。

照著做:七個步驟

1

先製造幾個檔案,認識「未追蹤」

在 git 看過它們之前,所有新檔案都是「未追蹤」。我們故意做幾個「不該進 repo」的檔案來練習。以下在你的 repo 資料夾(第 1 篇 clone 下來的那個)裡執行。

echo "my-secret-key" > .env
echo "debug info" > debug.log
mkdir node_modules
echo "x" > node_modules/a.js
echo "我的筆記" > notes.txt
git status
你會看到Untracked files: 底下列出 .env、debug.log、node_modules/、notes.txt 四項。這時如果隨手 git add .,密碼檔也會被加進去。
2

建立 .gitignore

把不要的檔案寫成規則。.gitignore 是一個沒有副檔名的純文字檔,放在 repo 最外層,檔名開頭有一個點。

  1. 用任何文字編輯器新增檔案,存成 .gitignore(不是 .gitignore.txt)。
  2. 貼上下面的內容並存檔。
  3. 回到終端機再看一次 git status。
.gitignore 內容
# 密碼與環境設定
.env
# 記錄檔
*.log
# 套件資料夾
node_modules/
# 系統暫存檔
.DS_Store
Thumbs.db
git status
你會看到未追蹤清單只剩 .gitignore 與 notes.txt。.env、debug.log、node_modules/ 都消失了:它們被忽略了。
小技巧在 GitHub 建立 repo 時,可以勾 Add .gitignore 並選語言範本;GitHub 官方也維護一個範本集 repo(github/gitignore)可參考。
3

看懂規則寫法

規則不多,記住下面這幾種就能應付大部分情況。

寫法
意思
*.log
所有 .log 檔,不管在哪個資料夾。* 代表任意字元。
node_modules/
名叫這個名字的資料夾(結尾的 / 表示它是資料夾)。
/build
只限 repo 最外層的 build(開頭的 / 表示從根目錄算起)。
docs/*.tmp
只限 docs 資料夾底下的 .tmp 檔。
**/cache
任何深度的 cache。
!keep.log
例外:即使前面的規則擋住,這個仍要追蹤(! 代表反向)。
# 註解
以 # 開頭的行是註解,git 會略過。
注意反向規則 ! 有一個限制:如果上層資料夾已經被忽略,資料夾裡的檔案就無法再用 ! 放行。放行要連資料夾一起寫。
4

查「為什麼這個檔案被忽略」

規則一多,你會想知道某個檔案到底是被哪一行擋住的。

git check-ignore -v debug.log
你會看到輸出 .gitignore:3:*.log debug.log:意思是檔案 .gitignore 的第 3 行規則 *.log 擋住了它。
5

檔案已經 commit 過,再寫規則「沒有用」怎麼辦

.gitignore 只管「還沒被追蹤」的檔案。已經進了歷史的檔案,要先叫 git 停止追蹤(檔案本身不會被刪掉)。

git rm --cached .env
git commit -m "停止追蹤 .env"
# 整個資料夾要加 -r:
# git rm -r --cached node_modules
你會看到git rm --cached 顯示 rm '.env';你的資料夾裡 .env 仍然存在。
重要這只是「從現在起不再追蹤」。它在過去的 commit 裡仍然存在。如果那是真的密碼或金鑰,請當作已外洩,立刻去服務端更換,並看第 10 篇。
6

看改了什麼:git diff

commit 之前,先看一眼「這次到底改了什麼」,是避免誤 commit 的好習慣。先讓 notes.txt 成為已追蹤檔案,再修改它。

git add .gitignore notes.txt
git commit -m "新增 .gitignore 與筆記"
echo "第二行" >> notes.txt
git diff
git add notes.txt
git diff --staged
1 我的筆記
2+第二行
你會看到第一個 git diff 顯示尚未 add 的變更;綠色 + 是新增、紅色 − 是刪除。add 之後要加 --staged 才看得到暫存區的差異。
7

看歷史:git log

歷史是 commit 串成的清單。學會看它,你就知道專案怎麼走到現在。

git commit -m "補充第二行"
git log --oneline -n 5
git show --stat HEAD
git log --oneline -- notes.txt
  1. git log --oneline -n 5:最近 5 筆,每筆一行。
  2. git show --stat HEAD:最新那筆 commit 改了哪些檔案。
  3. git log --oneline -- notes.txt:只看動過這個檔案的 commit。
你會看到每行開頭是 7 個字元的代號(commit 的名字),後面是你寫的說明。最新的在最上面。
小技巧git log 太長會進入分頁模式,按 q 離開。

初學者最常卡住的四個地方

我加了規則,檔案還是出現在 git status

依序檢查三件事:

  1. 檔案是不是已經被追蹤過?是的話照步驟 5 先 git rm --cached。
  2. 檔名是不是 .gitignore.txt?Windows 預設會隱藏副檔名,打開「顯示副檔名」確認。
  3. 用 git check-ignore -v 檔名 看有沒有任何規則命中。沒有命中就是規則寫錯了。
我想讓全部專案都忽略 .DS_Store,不想每個 repo 都寫

設一份全域忽略清單,只對你自己的電腦有效:

echo ".DS_Store" >> ~/.gitignore_global
git config --global core.excludesfile ~/.gitignore_global

團隊共用的規則仍然寫在專案裡的 .gitignore。

.env 要忽略,但別人需要知道有哪些設定項目

慣例是另外提交一份只有欄位名稱、沒有真實值的範例檔 .env.example,並在 .gitignore 裡放行它:

.env
!.env.example
空資料夾沒有出現在 git status

git 只追蹤檔案,不追蹤空資料夾。想保留空資料夾,慣例是在裡面放一個空檔案,常見取名 .gitkeep。

mkdir logs
echo "" > logs/.gitkeep
