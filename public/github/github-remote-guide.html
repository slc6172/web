origin 是你的雲端副本

用「雲端共用文件」來想

你的電腦上有一份工作副本,GitHub 上有一份雲端版本。兩份要靠三個動作保持一致:fetch(只是看看雲端有什麼新東西)、pull(看,而且直接併進來)、push(把你的新進度送上去)。

另一個重點是登入:GitHub 不收帳號密碼,要用瀏覽器授權、Personal Access Token(PAT)或 SSH 金鑰三者之一。

五個名詞

名詞
白話說明
remote
遠端:別的地方的那份 repo。git remote -v 可以列出來。
origin
你 clone 時,git 替來源取的預設名字。
origin/main
你的電腦記下來的「上次看雲端時,它的 main 長怎樣」。要 fetch 才會更新。
fetch / pull
fetch 只更新 origin/main,不動你的檔案;pull 是 fetch 再加 merge,會動你的檔案。
PAT / SSH
兩種證明身分的方式:一串像密碼的 token,或一對金鑰(私鑰留在你電腦,公鑰交給 GitHub)。

全貌:一個本機分支背後有三個位置

看懂「origin/main」是中間那一格,就看懂了 fetch 與 pull 的差別。

  1. 1fetch:把雲端的新進度抓到 origin/main(不動你的檔案)。
  2. 2merge:把 origin/main 併進你的 main。
  3. 3push:把你的 main 送到雲端。
  4. =pull 就是 1 加 2 一次做完。

照著做:七個步驟

1

看目前的遠端是哪裡

連不上或登入錯,第一件事就是看遠端網址指到哪。

git remote -v
你會看到四行輸出:origin 的 (fetch) 與 (push) 各一行,網址是 https://github.com/{me}/{repo}.git 或 git@github.com:{me}/{repo}.git。前者是 HTTPS,後者是 SSH。
2

fetch:先看雲端有什麼新東西

fetch 很安全,它只是把雲端的新進度抓下來放在 origin/main,不會改動你正在編輯的檔案。

git fetch
git status
git log --oneline main..origin/main
你會看到git status 可能顯示 Your branch is behind 'origin/main' by 2 commits;最後一個指令列出「雲端有、你還沒有」的 commit。沒有新東西時什麼都不會顯示。
3

pull:把雲端的新進度併進來

pull 等於 fetch 加 merge。建議先設定一次,讓行為單純可預期。

git config --global pull.rebase false
git pull
你會看到Fast-forward 與更新的檔案清單;已經是最新時顯示 Already up to date.。
小技巧pull.rebase false 代表用 merge 來整合,是新手最容易理解的方式。第一次 pull 遇到 divergent branches 提示,就是因為這個選項還沒設。
4

push:把你的 commit 送上去

新分支第一次 push 要加 -u,讓 git 記住它對應雲端哪個分支,以後只要打 git push。

git push
# 新分支的第一次:
# git push -u origin 分支名稱
你會看到最後幾行有 main -> main。
5

登入方式 A:瀏覽器授權或 Personal Access Token(HTTPS)

網址是 https:// 開頭時用這一條。多數新版 Git(Windows、macOS 的標準安裝)附帶 Git Credential Manager,第一次 push 會跳出瀏覽器請你登入並授權,完成後自動記住,這是最省事的做法。

  1. 若沒有跳出瀏覽器、而是要求輸入密碼,就要改用 token:到 GitHub 右上角頭像 → Settings → 最底下 Developer settings → Personal access tokens。
  2. 建立一個 Fine-grained token:只選你要用的 repo,權限 Contents 設為 Read and write,設定到期日,按 Generate token。
  3. 把 token 複製起來(只會顯示一次)。下次終端機問 Password 時,貼上 token 當密碼;Username 填你的帳號。
安全token 等於密碼。不要貼在聊天、不要寫進程式碼、不要 commit 進 repo(見第 10 篇)。設到期日,不用時就到同一頁撤銷。
6

登入方式 B:SSH 金鑰

網址是 git@github.com: 開頭時用這一條。你會產生一對金鑰:私鑰留在你電腦,公鑰交給 GitHub。之後不用再輸入任何密碼。

ssh-keygen -t ed25519 -C "{email}"
# 一路按 Enter 接受預設值(可設 passphrase)
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
  1. 複製最後一個指令印出的整行內容(ssh-ed25519 … 開頭)。
  2. GitHub 右上角頭像 → Settings → SSH and GPG keys → New SSH key。
  3. Title 取個辨識用的名字(例如 my-laptop),Key 貼上剛才複製的內容,按 Add SSH key。
  4. 回終端機測試連線。
ssh -T git@github.com
你會看到第一次會問是否信任主機,輸入 yes。成功時顯示 Hi 你的帳號! You've successfully authenticated, but GitHub does not provide shell access.。這就是成功,不是錯誤。
重要只能貼 .pub 結尾的公鑰。沒有 .pub 的那個檔案是私鑰,絕對不能分享、貼上或 commit。
7

把既有 repo 的網址換成 SSH(或換回 HTTPS)

clone 時用的是哪種網址,就會繼續用那種。想換,只要改 origin 的網址。

git remote set-url origin git@github.com:{me}/{repo}.git
git remote -v
# 換回 HTTPS:
# git remote set-url origin https://github.com/{me}/{repo}.git
你會看到git remote -v 顯示的網址已經是新的那一種。

初學者最常卡住的六個地方

! [rejected] main -> main (fetch first) 或 non-fast-forward

雲端有你這邊沒有的新 commit,git 不讓你直接蓋過去。先把雲端的併進來,再 push:

git pull
git push

如果 pull 時出現衝突,照第 3 篇的方式解決,再 push。不要用 --force 硬蓋,那會洗掉別人的 commit。

remote: Permission to … denied to 某個帳號(403)

你現在登入的是「某個帳號」,它對這個 repo 沒有寫入權限。常見原因:電腦裡存了另一個帳號的登入資訊,或 clone 的是別人的 repo。

先看 git remote -v 是不是你自己的 repo。若是別人的專案,請走 fork 流程(見第 6 篇)。若存了舊帳號的憑證,在 Windows 到「認證管理員」、macOS 到「鑰匙圈存取」刪掉 github.com 的項目,下次 push 重新登入。

Permission denied (publickey)

SSH 沒有認出你的金鑰。依序檢查:

  1. 公鑰有沒有貼到 GitHub 的 SSH and GPG keys。
  2. ssh-add -l 有沒有列出你的金鑰;沒有就重做步驟 6 的 ssh-add。
  3. 用 ssh -T git@github.com 單獨測試。
Authentication failed 或一直要求密碼

GitHub 不再接受帳號密碼登入 Git。改用步驟 5(瀏覽器授權或 token)或步驟 6(SSH)。貼上 token 時畫面不會顯示字元,這是正常的。

fatal: refusing to merge unrelated histories

兩邊的歷史完全沒有共同祖先,常見於「本機 git init、GitHub 上又勾了 README」的情況。確定要把兩邊接起來才加參數:

git pull origin main --allow-unrelated-histories
第一次 pull 出現 hint: You have divergent branches

git 要你選一種整合方式。依步驟 3 設定 pull.rebase false,再重打 git pull。
