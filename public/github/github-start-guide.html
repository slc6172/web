GitHub 入門 · 第 1 篇 · 第一次推送

從零到第一次 push:五個指令就夠

給完全沒碰過 git 的你。先分清楚 Git 與 GitHub,再用 clone、add、commit、push 把第一個檔案送上 GitHub。每一步都說明為什麼要做、要打什麼、會看到什麼。

TL;DR Git 在你的電腦上記錄存檔點,GitHub 是把存檔點放上雲端的網站。流程只有四個動作:clone(抓下來)→ add(挑檔案)→ commit(存檔)→ push(送上去)。

Git 和 GitHub 是兩個東西

用「遊戲存檔」來想

Git 是裝在你電腦上的工具,像遊戲的存檔系統:每次 commit 就是一個存檔點,隨時能回頭看、回到過去。它不需要網路。

GitHub 是放 Git 專案的雲端網站:把存檔點備份上去、讓別人看到、一起討論與合作。沒有 GitHub 也能用 Git;有了 GitHub,才能備份與協作。你要學的就是「怎麼把本機的存檔點送上去」。

七個會一直出現的名詞

名詞
白話說明
repo
一個專案的資料夾,連同它所有的歷史紀錄。
commit
一個存檔點:把某一刻的檔案狀態連同一句說明記下來。
暫存區(staging)
commit 之前的「取景框」。你用 git add 決定這次存檔要包含哪些檔案。
remote / origin
遠端:GitHub 上的那份 repo。origin 是 git 替它取的預設名字。
clone
把 GitHub 上的 repo 整份抓到你的電腦。通常只做一次。
push
把本機新的 commit 送到 GitHub。
main
預設的主要分支名稱。新手階段你只會待在這條分支上。

全貌:一次推送只有四個動作

先看地圖,後面每一步都會回到這張圖。左邊三個方塊在你的電腦,右邊在 GitHub。

  1. 1add:把改好的檔案放進暫存區。
  2. 2commit:把暫存區的內容存成一個存檔點。
  3. 3push:把存檔點送上 GitHub。
  4. 4clone:一開始把 GitHub 上的 repo 抓到電腦(只做一次)。

照著做:八個步驟

1

註冊 GitHub 並安裝 Git

GitHub 是網站,Git 是要裝在電腦上的程式,兩個都要有。

  1. 到 github.com 按 Sign up,依畫面建立帳號並驗證 email。
  2. 安裝 Git:Windows 到 git-scm.com 下載安裝(預設選項即可,會附帶 Git Bash);macOS 在終端機打 xcode-select --install;Ubuntu / Debian 打 sudo apt install git。
  3. 開一個終端機(Windows 用 Git Bash),輸入下面指令確認安裝成功。
git --version
你會看到類似 git version 2.45.0 的一行(數字依你的版本而不同)。
2

告訴 Git 你是誰(只做一次)

每個 commit 都會記錄作者。還沒設定的話,第一次 commit 會失敗並顯示 Author identity unknown。

git config --global user.name "{name}"
git config --global user.email "{email}"
git config --global init.defaultBranch main
git config --global --list
你會看到--list 的輸出裡有你剛設的 user.name、user.email 與 init.defaultBranch=main。
注意email 要和 GitHub 帳號的 email 一致,commit 才會算在你的帳號底下。想隱藏真實 email,可到 GitHub 的 Settings → Emails 取得 noreply 位址來用。
3

在 GitHub 網頁上建立一個 repo

先有雲端的家,才有東西可以 clone 與 push。

  1. 登入 GitHub,按右上角的 + → New repository。
  2. Repository name 填 {repo}。
  3. 選 Public(公開)或 Private(私人)。練習用哪個都可以。
  4. 勾選 Add a README file,讓 repo 一開始不是空的。
  5. 按 Create repository。
你會看到跳到 github.com/{me}/{repo},頁面列出一個 README.md 檔案。
小技巧新手建議勾 README:repo 不是空的,下一步 clone 最簡單。
4

Clone:把 repo 抓到電腦

clone 會把整份 repo 與歷史抓下來,並自動把雲端那份取名 origin,所以你不需要再手動設定遠端。

git clone https://github.com/{me}/{repo}.git
cd {repo}
git status
你會看到終端機顯示 Cloning into '{repo}'...;git status 顯示 On branch main 與 Your branch is up to date with 'origin/main'。
檢查cd {repo} 之後,後面所有 git 指令都要在這個資料夾裡打。
5

新增或修改一個檔案

這是你平常就會做的事:改檔案。Git 此時已經知道有變化,但還沒有記錄。

echo "我的第一次推送" > hello.txt
git status
你會看到Untracked files: 底下列出 hello.txt(通常是紅色)。意思是:這個檔案 git 還不認識。
6

add:放進暫存區

暫存區讓你挑選「這次存檔要包含什麼」。例如你改了五個檔案,卻只想先存其中兩個。

git add hello.txt
git status
你會看到Changes to be committed: 底下出現 new file: hello.txt(通常是綠色)。
小技巧git add . 會一次加入全部變更。用之前先看 git status,避免把不該進 repo 的檔案也加進去(見第 2 篇 .gitignore)。
7

commit:存成一個存檔點

-m 後面接這次存檔的說明。寫成「改了什麼」,以後翻歷史才看得懂。

git commit -m "新增 hello.txt"
git log --oneline
你會看到1 file changed, 1 insertion(+);git log --oneline 最上面一行是 7 個字元的代號加上你的說明。
注意如果畫面跳進一個文字編輯器(忘了 -m),在 vim 裡按 Esc,輸入 :q! 再按 Enter 離開,然後補上 -m 重打。
8

push:送上 GitHub

到這一步,commit 還只存在你的電腦。push 才會把它送到 GitHub。

git push
  1. 第一次 push 可能要求登入:瀏覽器會跳出授權視窗(Git Credential Manager),照畫面登入即可。
  2. 回到 github.com/{me}/{repo} 重新整理頁面。
你會看到終端機最後幾行有 main -> main;網頁上出現 hello.txt,旁邊顯示你寫的 commit 說明。
注意登入時不能用 GitHub 密碼。若終端機要求密碼並顯示 Authentication failed,請看下方「常見卡關」與第 4 篇。

初學者最常卡住的六個地方

fatal: not a git repository

你所在的資料夾不是 repo。用 pwd(Windows 的 Git Bash 也可用)確認位置,cd 進 clone 下來的資料夾再試一次。

Author identity unknown(commit 失敗)

還沒設定 user.name 與 user.email,回到步驟 2 設定,再重打一次 git commit。

push 時要求輸入密碼,卻顯示 Authentication failed

GitHub 已不接受用帳號密碼登入 Git。解法是:使用 Git Credential Manager 的瀏覽器授權,或改用 Personal Access Token 或 SSH 金鑰。設定細節在第 4 篇「遠端與同步」。

我的分支叫 master,不是 main

舊版 Git 的預設分支叫 master。步驟 2 已設定新專案預設用 main。現有專案想改名:

git branch -M main
我已經有一個本機專案,想把它放上 GitHub(不是 clone)

先在 GitHub 建一個空的 repo(不要勾 README),再在你的專案資料夾裡:

git init
git add .
git commit -m "第一次提交"
git branch -M main
git remote add origin https://github.com/{me}/{repo}.git
git push -u origin main

這裡的 git remote add origin 就是 clone 幫你自動做的那一步。

中文檔名在 git status 裡變成一串 \346\226...

這只是顯示方式,檔案本身沒壞。下面這行讓 git 直接顯示中文檔名:

git config --global core.quotepath false
