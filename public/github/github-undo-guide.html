先判斷狀況,再選指令:多數錯誤都能救

改錯、add 錯、commit 錯、push 錯,各有不同的收回方式。這一篇先教你判斷錯誤走到哪一層,再配上對應的指令,最後教你用 reflog 救回「消失」的 commit。

TL;DR 還沒 push 可以改寫歷史(restore / amend / reset);已經 push 就用 revert 新增反向 commit。用 --hard 之前先看 git status;真的搞丟了,git reflog 通常救得回來。

多數錯誤都能救,關鍵是先判斷「走到哪一步了」

用「寫文章」來想

你有一份稿子:改到一半的草稿(工作資料夾)、挑好要交的段落(暫存區)、已經存檔的版本(本機歷史)、已經寄給別人的版本(GitHub)。想「收回」一個錯誤,要看它現在在哪一層:越往右,動它的影響越大。

原則只有一句:還沒 push 的,可以改寫歷史;已經 push 的,用新增反向 commit 的方式收回。

全貌:每個指令作用在哪一層

看圖選指令:你的錯誤在哪一層,就用作用在那一層的指令。

  1. 1restore:工作資料夾回到暫存區(或上次 commit)的樣子。
  2. 2restore --staged:從暫存區退回工作資料夾,修改保留。
  3. 3reset:本機歷史往回退。只用在還沒 push 的。
  4. 4revert:新增反向 commit,不改歷史。已 push 的用它。

照著做:七個步驟

1

動手前:先看清楚現況

還原的第一步永遠是看狀態,不是下指令。你要知道錯誤在哪一層。

git status
git log --oneline -n 5
git diff
你會看到status 告訴你哪些檔案已修改或已 add;log 看最近的 commit;diff 看未 add 的內容。
小技巧不確定時,先建一個備份分支:git branch backup。出了狀況還能回來,而且完全不影響目前工作。
2

丟掉未 add 的修改:restore

改壞了,想回到上次 commit 的樣子。

git restore notes.txt
git status
你會看到notes.txt 回到上次 commit 的內容,不再列在 Changes not staged。
危險這個動作不可逆:被丟掉的修改沒有任何地方可以找回。不確定就先 git stash。
3

取消暫存:restore --staged

add 錯檔案時用。修改留在工作資料夾,只是不放進這次 commit。

git add secret.txt
git restore --staged secret.txt
git status
你會看到secret.txt 從 Changes to be committed 移到 Untracked files 或 Changes not staged。
4

改最近一次 commit:amend

訊息打錯、少加一個檔案,都可以修最近一次 commit。

git commit --amend -m "新增 notes.txt 並補上說明"
你會看到git log --oneline 最上面那筆的代號變了(因為它是一個新的 commit),舊的那筆被取代。
只用在還沒 pushamend 會改寫歷史。已經 push 的 commit 不要 amend,否則和別人的歷史對不上。
5

已經 push:revert

歷史已經被別人看到了,就不要改歷史。revert 另外再做一個「反向」的 commit,把錯誤抵銷掉。

git log --oneline -n 3
# 假設要收回的 commit 代號是 a1b2c3d
git revert a1b2c3d
git push
你會看到出現一個新的 commit,訊息是 Revert "…";檔案內容回到那個 commit 之前的樣子。若 revert 時出現衝突,和第 3 篇的做法一樣解決後 git revert --continue。
6

還沒 push:reset 三種模式

把目前分支移回較早的 commit。三種模式差別只在「對暫存區和工作資料夾怎麼處理」。

模式
暫存區
工作資料夾
--soft
保留(內容仍是已 add)
保留
--mixed(預設)
清空
保留(修改仍在,只是回到未 add)
--hard
清空
全部丟掉
git reset --soft HEAD~1    # 拆掉最後一個 commit,內容留在暫存區
git reset HEAD~1           # 預設 mixed:內容留在工作資料夾
git reset --hard HEAD~1    # 全部丟掉(小心)
你會看到HEAD~1 的意思是「往前一個 commit」。git log --oneline 少了最後一筆。
7

救回「消失」的 commit:reflog

reset --hard、刪錯分支之後,commit 其實還在,只是沒有名字指到它。reflog 記下了 HEAD 的每一次移動。

git reflog
# 找到出事之前的那一行,例如 e5f6a7b HEAD@{2}
git reset --hard e5f6a7b
你會看到reflog 每一行有代號、動作(commit、reset、checkout…)與說明。回到那個代號,你的 commit 又回來了。
小技巧reflog 只存在你的電腦,而且過一段時間(預設數十天)會被清理。出事後越早處理越好。

常見卡關

我想改很久以前的某個 commit

這需要 interactive rebase,風險比較高,而且只適用於還沒 push 的歷史。新手階段建議用 git revert 另外新增一個修正的 commit,更安全。

push 被拒絕,是不是該 --force?

幾乎都不要。被拒絕通常是因為雲端有你沒有的 commit,--force 會洗掉別人的工作。先 git pull,見第 4 篇。真的必須強制時用 --force-with-lease,並先和團隊確認。

我把密碼 commit 上去了,revert 就可以嗎?

不行。revert 只是新增一個反向 commit,舊的 commit 與密碼仍在歷史裡。請當作已外洩:先到服務端更換金鑰,再看第 10 篇處理歷史。

git reset 之後工作資料夾的檔案不見了

如果用了 --hard,未 commit 的修改已經丟了;已 commit 的內容可以用 git reflog 找回。下次用 --hard 前先 git status,或先 git branch backup。

我不小心在 main 上 commit,想改放到新分支

先用 git branch 新分支 把 commit 存到新分支,再把 main 退回去:

git branch fix-typo
git reset --hard origin/main
git switch fix-typo

前提是這些 commit 還沒 push,而且 main 上沒有其他想保留的未存修改。
